# 개미의 모험 — 첫 제작 버전 통합 기획서

- 문서 버전: v0.2 (기존 파일 갱신)
- 개정일: 2026년 11월 11일 (한국 시간)
- 사용 저장소: [dreamingchick/ant-adventure](https://github.com/dreamingchick/ant-adventure)
- 이번 개정: 최종 결혼 엔딩 5종과 진행 이력에 따른 분기 설계 추가. 저장소는 사용자 지정 정보이며, 코드 확인·커밋·배포를 수행한 것은 아니다.
- 작성일: 2026년 11월 11일 (한국 시간)
- 프로젝트: GP7-antadventure
- 목적: 대화에서 결정한 첫 제작 범위를 통합하고, 구현·검수의 기준을 정한다.
- 상태: 기획 정리 완료. 구현·배포·실기기 검수는 아직 수행하지 않았다.

> 작은 개미에게 거실은 대륙이고, 집으로 돌아가는 길은 모험이다.

## 1. 문서의 기준

- **확정**: 사용자가 직접 선택하거나 지정한 내용이다.
- **초기 제안**: 대화 중 제안했으나 개별 승인되지 않은 수치·연출·세부 규칙이다. 검수 전 조정할 수 있다.
- **설계 보완안**: 확정 규칙 사이의 빈틈을 메우기 위한 이번 문서의 제안이다. 기존 확정 사항을 변경하지 않는다.

이름·비용·시간·능력치의 구체적인 숫자는 별도 확정 표시가 없는 한 초기 제안이다. 뒤의 질문에서 추천안을 골랐다는 이유로 앞서 제시한 다른 제안까지 확정된 것으로 간주하지 않는다.

## 3. 이야기와 캐릭터

### 3.1 확정 설정

주인공은 기존 작품의 개미와 동일한 캐릭터다. 챠챠를 놀리다 길을 잃고, 귀갓길에서 베짱이 무리와 맞닥뜨린다.

베짱이들은 거실의 먹이와 길목을 차지하고 통행료를 요구하는 불량 무리다. 개미에게 놀림받은 악연도 있어, 주인공을 알아보고 더욱 집요하게 방해한다.

플레이어는 주인공의 이름을 직접 정한다. 설정에서 언제든 무료로 바꿀 수 있으며, 이름 변경은 진행·설탕·강화·기록에 영향을 주지 않는다.

챠챠는 도입과 중간의 짧은 장애물 구간에 등장한다. 거실 마지막 난관은 베짱이 대장과의 보스전이다.

전체 게임의 최종 결말은 개미와 베짱이의 결혼이다. 결혼의 모습은 그동안의 진행 현황에 따라 달라지며, 확정된 다섯 결말은 16절에 정의한다. 기존 귀환 목표는 초반 모험의 동기로 유지하고, 결혼을 전체 이야기의 종착점으로 확장한다. 배우자 베짱이의 정체와 관계 형성 과정은 아직 확정하지 않았다.

### 3.2 도입과 대사 — 초기 제안

개미가 챠챠를 놀리며 달아나다가 챠챠가 움직인 러그에 휩쓸려 낯선 곳으로 굴러간다. 몸을 털고 일어나지만, 익숙한 귀갓길은 보이지 않는다.

> 개미: “퉷! 여기까지 따라와 보시…… 어?”
>
> 개미: “……우리 집이 어느 쪽이더라?”

베짱이 길목에서는 다음과 같은 대화로 악연을 드러낸다.

> 평범한 베짱이: “저번에 침 뱉고 도망간 녀석이잖아!”
>
> 뚱뚱한 베짱이: “통행료 두 배. 내 과자에 침 뱉은 값까지.”
>
> 개미: “그건 과자가 아니라 네 발밑을 겨냥한 건데?”

이름을 비워 두면 ‘개미’를 기본 호칭으로 사용하는 것을 제안한다. 한글 이름이 자연스럽게 들어가도록 대사는 조사에 덜 의존하는 문장으로 작성한다.

## 4. 화면과 조작

### 4.1 확정 규칙

| 입력 | 동작 |
|---|---|
| 왼쪽 좌우 버튼 | 좌우 이동, 공중 위치 조절, 붙은 경로 따라 이동 |
| 오른쪽 점프 버튼 | 짧게 누르면 낮게, 길게 누르면 높게 점프 |
| 오른쪽 침 공격 버튼 | 한 번 누를 때 한 발 발사 |
| 상황별 상호작용 버튼 | 가능한 대상 근처에서 벽 붙기·물건 사용·실밥 잡기 |

침 공격과 상호작용은 별도 버튼이다. 공격 버튼을 누르고 있어도 자동 연사하지 않는다. 발사 간격과 침 게이지 조건을 만족해야 발사한다.

기기를 세로로 돌려도 가로형 게임 화면을 유지하며 계속 진행한다. 회전 안내와 회전으로 인한 자동 일시정지는 없다.

### 4.2 표시·입력 — 초기 제안 및 설계 보완안

| 기능 | PC 키 제안 |
|---|---|
| 이동 | ← / → |
| 점프 | Space |
| 침 공격 | Z |
| 상호작용 | X |
| 일시정지 | Esc |

스마트폰에서는 이동·점프·공격의 동시 입력을 지원한다. 상호작용 버튼은 현재 대상의 아이콘을 표시하며, 사용 가능한 대상이 없으면 숨기거나 비활성화한다.

여러 상호작용 대상이 겹치면 가장 가까운 유효 대상을 하나 선택하고 표시한다. 거리가 비슷할 때 대상이 계속 바뀌지 않도록 선택을 잠시 유지하는 보완안을 제안한다.

세로 방향에서는 게임 전체를 가로 구도로 회전·축척해 표시하고 입력 좌표도 함께 변환하는 보완안을 제안한다. 실제 기기의 화면 방향 잠금 지원 여부와 별개로 화면·터치가 일치해야 한다. 회전 중 눌린 입력이 남지 않게 해제하되 게임 진행은 멈추지 않는다.

카메라는 개미를 중앙보다 조금 왼쪽에 놓고 진행 방향을 넓게 보여주는 방식으로 제안한다. 위쪽 경로에서는 카메라도 따라 올라가며, 챠챠 구간은 위험 신호를 볼 수 있는 시야를 확보한다.

## 5. 이동과 상호작용

### 5.1 점프 — 확정

- 누르는 시간에 따라 높이가 달라진다.
- 최대 높이에 도달하면 상승이 끝난다.
- 점프·낙하 중 좌우로 착지 위치를 조절할 수 있다.

점프 높이와 침 사거리는 강화 대상에서 제외하는 초기 제안을 유지한다. 발판 간격의 학습이 강화 후에도 유효하도록 하기 위함이다.

### 5.2 벽·천장 타기 — 확정

- 표시된 표면에서 상호작용 버튼을 눌러 붙는다.
- 좌우 버튼으로 연결된 표면 경로를 양방향 이동한다.
- 모서리는 표면을 따라 몸의 방향을 전환한다.
- 점프 버튼으로 표면에서 이탈한다.
- 일반 표면은 시간제한 없이 붙을 수 있다.
- 일부 특수 표면은 일정 시간이 지나면 미끄러져 떨어진다.
- 붙어 있는 동안 침 공격은 불가능하다. 점프로 이탈하면 공중 공격이 가능하다.

**이전 매달리기 게이지·바닥 회복 규칙은 취소되었다. 구현하지 않는다.**

특수 표면의 유지 시간·경고 시점은 미정이다. 질감과 미끄러짐 동작으로 위험을 알리고, 첫 학습 장소 아래에는 안전한 발판을 두는 것을 제안한다. 재부착으로 제한시간을 무한 초기화하는 상황은 방지해야 한다.

### 5.3 물건 밀기·실밥 매달리기 — 확정 범위

가벼운 물건 밀기와 실밥 잡고 매달리기를 첫 버전에 포함한다. 기본 활용은 필수 경로에, 어려운 응용은 설탕 샛길에 배치한다.

| 행동 | 세부 조작 초기 제안 |
|---|---|
| 물건 밀기 | 상호작용으로 잡은 뒤 좌우 입력으로 밀고, 다시 누르면 놓기 |
| 실밥 잡기 | 가까운 실밥에서 상호작용으로 매달리고, 좌우로 흔들다가 점프로 이탈 |

실밥에 매달린 동안 공격 불가, 재시작 시 현재 구간 사물 초기화는 설계 보완안이다. 물건을 밀어 출구나 필수 통로를 영구적으로 막을 수 없게 하고, 필요하면 구간 사물 복원 기능을 제공한다.

## 6. 침 공격

### 6.1 확정 규칙

- 공격 동작은 침 뱉기다. 이전의 근접 타격 제안은 대체되었다.
- 바라보는 방향으로 짧은 거리를 직선 발사한다.
- 한 번 누를 때 한 발 발사한다.
- 침 게이지를 소모하며, 시간이 지나면 자동 회복한다.
- 지상·점프·낙하 중 공격 가능, 벽·천장 부착 중 공격 불가다.
- 공중에서도 바라보는 방향으로 수평 발사한다.
- 일반 적은 피해와 짧은 경직을 받으며, 체력 소진 시 퇴장한다.

### 6.2 수치 초기 제안

| 항목 | 기본 수치 제안 |
|---|---:|
| 침 사거리 | 개미 몸길이의 약 3배 |
| 최대 침 게이지 | 100 |
| 1회 소모량 | 25 |
| 최소 발사 간격 | 0.4초 |
| 회복 시작 대기 | 마지막 발사 후 1초 |
| 기본 회복 속도 | 초당 25 |
| 침 1발 피해 | 1 |
| 기본 일반 적 체력 | 2 |
| 일반 적 피격 경직 | 0.3초 |

침은 첫 적이나 벽에 맞으면 사라지는 것으로 제안한다. 잔량 부족 시 발사하지 않으며 공격 불가 피드백을 제공한다. 실패한 발사 입력은 회복 대기시간을 갱신하지 않는 보완안을 제안한다.

체크포인트 재시작·새 입장 시 침 게이지는 최대치, 최초 체크포인트 활성화 시에도 전부 회복하는 보완안을 제안한다. 체력 전부 회복과 달리 이 침 회복 세부 규칙은 별도 확정되지 않았다.

## 7. 적과 전투

### 7.1 일반 전투 — 확정

일반 적은 피해 가도 진행할 수 있고, 특정 전투 구간만 처치가 필수다. 필수 전투는 진입 전 인지할 수 있게 표시하는 것을 제안한다.

적은 다양한 베짱이로 구성한다. 아래 종류는 사용자 지정이며, 행동과 외형 세부 내용은 초기 제안이다.

| 종류 | 외형 제안 | 행동 제안 | 대응 방법 |
|---|---|---|---|
| 평범한 베짱이 | 초록 몸과 태평한 표정 | 순찰 후 접근 | 사거리 유지·침 공격 |
| 뚱뚱한 베짱이 | 둥근 배와 느린 걸음 | 준비 동작 후 짧은 배치기 | 점프로 회피 후 반격 |
| 마른 베짱이 | 긴 팔다리와 가는 몸 | 빠른 접근 후 후퇴 | 접근 순간 명중·경직 활용 |
| 똑똑한 베짱이 | 안경과 계산하는 표정 | 조준 후 씨앗 발사 | 조준 위치 이탈 후 접근 |

각 적의 체력·속도·공격 간격은 미정이다. 첫 버전에서 적 조합이 회피 불가능한 공격을 만들지 않게 한다. 제압 연출은 코믹하게 뒤집혔다가 도망가는 방식으로 제안한다.

### 7.2 베짱이 대장 — 확정

- 거실 마지막 난관으로 등장한다.
- 언제든 피해를 줄 수 있다. 공격 직후의 빈틈이 가장 안전한 공격 기회다.
- 체력 50% 이하에서 기존 공격이 조금 빨라진다.
- 후반에 새 공격 패턴을 추가하지 않는다.
- 최초 처치 시 설탕 보상을 지급하고 다음 길을 연다.
- 첫 버전은 거실 클리어·강화 화면까지 제공한다. 후속 지역과 최종 결혼 엔딩은 이번 첫 버전의 제작 범위 밖이다. 최종 엔딩 기획은 16절을 따른다.

| 패턴 초기 제안 | 사전 신호 | 대응 |
|---|---|---|
| 배치기 돌진 | 몸을 뒤로 젖히고 발 구르기 | 점프 또는 벽 타기 |
| 내려찍기 | 팔을 들고 멈추기 | 착지 범위 이탈 |
| 공격 후 숨 고르기 | 배를 붙잡고 헉헉거리기 | 접근해 침 공격 |

일반 침 한 발로 보스 행동이 취소되지 않는 규칙을 제안한다. 2단계에서는 돌진 속도 약 15% 증가, 공격 후 빈틈 유지, 준비 신호 시간 유지로 시작한다. 보스 체력·크기·공격 주기·첫 보상량은 플레이 검수 후 조정한다.

## 8. 체력·실패·체크포인트

### 8.1 확정 규칙

| 항목 | 규칙 |
|---|---|
| 기본 체력 | 하트 3개 |
| 일반 피해 | 하트 1개 감소 |
| 하트 소진 | 최근 체크포인트에서 최대 체력으로 재시작 |
| 재도전 | 횟수 무제한 |
| 체크포인트 위치 | 중간과 주요 난관 직전에 고정 배치 |
| 체크포인트 최초 활성화 | 강화가 반영된 최대 체력까지 회복 |
| 활성화 지점 재방문 | 추가 체력 회복 없음 |
| 회복 아이템 | 정해진 위치에서 하트 1개 회복 |
| 최대 체력일 때 | 회복 아이템을 먹지 않고 남겨둠 |

회복 아이템의 작은 꿀방울 외형, 현재 구간 재시작 시 회복 아이템 복원은 초기 제안이다. 피격 후 짧은 무적, 추락 시 하트 1개 감소 후 안전 지점 복귀도 초기 제안이며, 마지막 하트를 잃으면 체크포인트 재시작으로 연결한다.

### 8.2 적 복원 — 확정

| 대상 | 하트 소진 후 처리 |
|---|---|
| 현재 체크포인트 구간 일반 적 | 시작 위치·최대 체력으로 초기화 |
| 현재 구간 필수 전투 | 처치 진행도 초기화 |
| 이전 완료 구간 | 완료 상태 유지 |
| 보스 | 최대 체력·초기 전투 상태로 복원 |

체크포인트 이전 구간과 현재 구간의 경계를 명시적으로 구분해야 한다. 스테이지 시작점은 최초 체크포인트와 같은 복원 기준으로 취급하는 보완안을 제안한다.

## 9. 설탕과 강화

### 9.1 설탕 획득 — 확정

- 획득 경로는 맵에 배치된 설탕과 보스 최초 처치 보상이다.
- 일반 적 처치 보상과 별도 클리어 보상은 없다.
- 클리어한 스테이지를 새로 플레이하면 일반 설탕이 다시 배치된다.
- 보스 최초 보상은 재지급하지 않는다.
- 기본 경로와 선택 샛길에 설탕을 배치한다.

### 9.2 수집 확정·실패 — 확정

| 상황 | 처리 |
|---|---|
| 맵 설탕 획득 | 임시 보유 |
| 체크포인트 도착 | 해당 지점까지 수집 확정 |
| 클리어 | 남은 임시 보유분까지 확정 |
| 하트 소진 | 마지막 체크포인트 이후 수집분만 회수, 원래 위치 복원 |
| 일반 피격 | 설탕 유지 |
| 하트가 남은 추락 | 설탕 유지 |

확정한 설탕을 같은 플레이 안에서 다시 얻을 수 없어야 한다. 중도 포기 후 처음부터 재도전하더라도, 미클리어 회차의 확정 수집분은 재배치하지 않는 보완안을 제안한다. 전체 재배치는 클리어 후 새 회차에만 수행한다.

### 9.3 강화 — 확정

- 클리어 후 스테이지 사이 준비 화면에서만 강화한다.
- 스테이지 내부·체크포인트·일시정지 메뉴에서는 강화할 수 없다.
- 항목은 최대 체력, 최대 침 게이지, 침 회복 속도다.
- 각 항목은 기본 상태에서 최대 3단계까지 강화한다.
- 세 항목은 같은 단계에서 비용이 같고, 단계가 높아질수록 비싸진다.
- 항목별 비용은 독립적으로 계산한다. 다른 항목 구매로 비용이 오르지 않는다.
- 설탕을 사용하지 않고 보유할 수 있다.

### 9.4 강화 수치·비용 — 초기 제안

| 항목 | 기본 | 1단계 | 2단계 | 3단계 |
|---|---:|---:|---:|---:|
| 최대 하트 | 3 | 4 | 5 | 6 |
| 최대 침 게이지 | 100 | 125 | 150 | 175 |
| 초당 침 회복 | 25 | 30 | 35 | 40 |
| 해당 단계 구매 비용 | — | 20 | 40 | 60 |

한 항목 총비용은 120개, 세 항목 완전 강화는 360개다. 침 소모량을 25로 유지하면 최대 연속 발사 가능량은 기본 4발에서 3단계 7발까지 증가한다. 실제 회복·발사 간격에 따라 장시간 연사는 달라진다.

일반 설탕 총량과 보스 최초 보상량은 미정이다. **첫 클리어 후 최소 한 번 강화할 수 있는 양**을 기준으로 초기 배치를 조정하는 것을 제안한다. 첫 클리어 전에 강화가 불가능하므로 필수 경로와 보스는 반드시 기본 능력으로 검수한다.

## 10. 저장·이어 하기·기록

### 10.1 확정

체크포인트·강화·클리어 시 자동 저장한다. 종료 후 최근 체크포인트부터 이어 할 수 있다. 미확정 설탕은 저장하지 않고 원래 위치에 복원한다.

플레이어는 이어 하기 또는 현재 진행을 포기하고 처음부터 재도전을 선택할 수 있다. 확정 설탕·강화·클리어 기록·이름은 유지된다.

| 저장 정보 | 내용 |
|---|---|
| 플레이어 | 이름 |
| 성장 | 확정 설탕 잔액, 세 항목 강화 단계 |
| 진행 | 회차, 스테이지, 체크포인트, 이전 구간 완료 상태 |
| 수집 | 현재 회차의 확정 수집 설탕 식별 정보 |
| 보상 | 보스 최초 보상 수령 여부 |
| 기록 | 개인 최고 클리어 기록 |

최종 엔딩이 도입되는 버전에서는 진행 이력·관계 지표·결혼 엔딩 이력 저장을 추가한다. 16절의 저장 필드는 후속 설계안이며, 첫 거실 버전에 이미 구현된 기능을 뜻하지 않는다.

온라인 계정 동기화·기기 간 이전·수동 슬롯은 첫 버전에 포함하지 않는다. 동일 기기·동일 브라우저의 로컬 저장으로 시작하는 것은 구현 제안이다.

### 10.2 기록과 복원 — 초기 제안 및 설계 보완안

- 조작 시작부터 보스 격파까지 시간을 측정한다.
- 주요 정지 대화·일시정지·게임을 닫아 둔 시간은 제외한다.
- 같은 실행 중 실패 이전 시간은 누적한다.
- 처음부터 재도전을 선택하면 이번 도전 시간은 새로 시작한다.
- 최고 기록 달성 당시 강화 단계도 표시한다.
- 체크포인트 저장 시 누적 시간도 함께 저장한다. 재접속은 저장된 누적 시간에서 재개한다. 마지막 저장 이후 경과 시간의 정확한 보존은 별도 구현 검토 항목이다.
- 정식 이어 하기는 체크포인트 재시작 규칙에 맞춰 체력·적·사물 상태를 복원한다. 현재 구간 적을 일부만 처치한 상태까지 임의로 보존하지 않는다.

강화 구매는 설탕 차감과 단계 증가를 한 번에 저장하고, 보스 최초 보상도 수령 표식과 잔액을 함께 저장해 중복 지급을 막는다. 이름 변경은 즉시 저장하는 것을 제안한다.

## 11. 시각·대사·사운드 — 확정 방향

| 요소 | 방향 |
|---|---|
| 그래픽 | 기존 개미 디자인을 계승한 부드러운 만화풍 |
| 챠챠 | 기존 작품의 동일 캐릭터로 식별 가능하게 제작 |
| 베짱이 | 체형·표정·소품·동작으로 종류 구분 |
| 배경 | 개미 시점에서 거대하게 보이는 거실 |
| 일반 대사 | 이동을 멈추지 않는 짧은 말풍선 |
| 주요 대사 | 도입·보스 등장·클리어 등에서 정지 대화 |

발판·위험물·붙을 수 있는 표면은 배경과 명확히 구분한다. 말풍선은 발판·공격 준비 신호·조작 버튼을 가리지 않는다. 주요 대화 건너뛰기와 보스 재도전 시 등장 대사 생략은 초기 제안이다.

배경음악·효과음·감탄사는 각각 음량 조절 및 음소거를 제공하는 보완안을 제안한다. 소리를 꺼도 모든 위험을 시각적으로 인지할 수 있어야 한다. 음원 제작 방식과 실제 감탄사 자산은 미정이다.

## 12. 거실 스테이지 구간 설계 — 전체 초기 제안

아래 순서는 확정 시스템을 검수하기 위한 배치안이다. 최종 맵 길이·좌표·배치 수량을 확정한 것은 아니다.

| 순서 | 구간 | 주요 플레이 | 배치·학습 |
|---|---|---|---|
| 0 | 길을 잃은 개미 | 챠챠와 도입 소동 | 정지 대화·이름 반영 |
| 1 | 소파 아래 | 안전한 이동과 높이가 다른 턱 넘기 | 좌우·짧은 점프·높은 점프·설탕 |
| 2 | 탁자 다리 | 벽·천장 경로 이동 | 붙기·모서리·이탈, 안전한 특수 표면 체험 |
| 3 | 베짱이 길목 | 평범한 적과 뚱뚱한 적 개별 학습 | 침·게이지 회복·선택 우회, 중간 체크포인트 |
| 4 | 생활용품 사이 | 물건 밀기와 실밥 하나 건너기 | 필수 기본 활용, 어려운 설탕 샛길 |
| 5 | 챠챠의 장난 | 앞발·코·꼬리 움직임 통과 | 그림자와 준비 동작, 안전 대기 공간 |
| 6 | 출구 앞 소동 | 마른 적·똑똑한 적 학습 후 짧은 조합 전투 | 필수 처치 구간, 회복 아이템 |
| 7 | 대장의 길목 | 체크포인트 후 보스전 | 두 패턴, 체력 절반 이하 가속 |
| 8 | 거실 탈출 | 최초 보상·수집 확정·기록 정산 | 클리어 → 강화 → 거실 재도전 |

최초 3~5분 목표와 상호작용·적 4종 학습량이 충돌할 수 있다. 안내를 짧게 하고 각 학습 구간을 한 화면 안팎으로 제한하되, 초회 검수에서 시간이 초과되면 시간 목표를 조정한다. 핵심 학습을 생략해 목표 시간에 억지로 맞추지 않는다.

챠챠는 공격으로 쓰러뜨리는 대상이 아닌 환경 장애물로 제안한다. 베짱이 보스전과 챠챠 장애물의 위험을 동시에 중첩하지 않는다.

## 13. 첫 버전 범위

### 포함 — 확정

- 거실 1개 스테이지와 베짱이 대장 보스전.
- 다양한 베짱이 4종을 기준으로 한 적 구성.
- 좌우 이동·높이 조절 점프·벽과 천장 타기·특수 표면.
- 물건 밀기·실밥 매달리기·짧은 직선 침 공격.
- 하트·침 게이지·회복 아이템·체크포인트.
- 설탕 수집·회차별 재배치·3항목 각 3단계 강화.
- 자동 저장·이어 하기·처음부터 재도전·개인 기록.
- 직접 작명·무료 이름 변경.
- 만화풍 그래픽·대사·음악·효과음·짧은 감탄사.
- 스마트폰 터치·PC 키보드, 기기 회전에도 가로형 진행 유지.

### 첫 버전 범위 밖

- 다음 지역의 실제 플레이와 최종 결혼 엔딩 5종의 구현. 결혼 엔딩의 전체 기획은 본 문서에 포함한다.
- 온라인 랭킹·멀티플레이·계정 동기화.
- 게임패드·2단 점프·근접 공격·긴 사거리·포물선 침.
- 벽 타기 소모 게이지·벽/천장 부착 중 침 공격.
- 일반 적 설탕 드롭·별도 클리어 설탕 보상.
- 인게임 강화·3단계 초과 강화·필수 강화를 요구하는 첫 클리어.

| 설탕 반복 플레이 | 클리어 후 새 회차 재배치, 보스 최초 보상 중복 지급 없음 |

| 저장 | 종료·재접속 후 이름·잔액·강화·체크포인트·최초 보상·기록 일치 |
| 대사·사운드 | 말풍선이 위험을 가리지 않음, 정지 대화 중 적·투사체 피해 없음 |
| 학습·난도 | 초반 안전 학습, 후반 조합, 강화 없는 첫 클리어 가능 |
| 진행 완결 | 새 게임 → 이름 → 거실 → 보스 → 정산 → 강화 → 재도전 흐름 완주 |

회전은 최소한 실제 Android 기기에서 검수하고, PC에서는 키보드와 화면 크기 변화까지 확인한다. 추가 지원을 표방하는 브라우저·기기는 별도로 검수해야 한다.

## 15. 구현 전 조정할 항목

핵심 선택을 다시 묻기보다 아래 항목은 초기값을 적용해 검수하고, 결과에 따라 조정한다.

1. 이동 속도·점프 곡선·공중 제어·피격 무적 시간.
2. 특수 표면의 유지 시간·재부착 제한·진행 방향 표시.
3. 베짱이별 체력·속도·공격 주기, 보스 체력과 가속 폭.
4. 설탕 총배치량·샛길 보상량·보스 최초 보상량·강화 비용.
5. 체크포인트 개수·위치·회복 아이템 배치.
6. 물건 밀기와 실밥의 정확한 입력·복원·충돌 규칙.
7. 세로 기기에서 가로형 화면을 유지하는 표시·입력 방식의 실제 사용성.
8. 종료 직전 경과 시간 보존 범위, 저장 실패 안내와 저장 형식 호환.
9. 기존 개미·챠챠 원본 자산의 실제 확인과 동작별 추가 제작 범위.
10. 배우자 베짱이의 정체·등장 시점, 관계 이벤트, 엔딩 분기 지표와 임계값.
11. 전체 스테이지 수·귀환 달성 시점·결혼에 이르는 후반 이야기 구성.

문서의 최종 목표는 거실 한 구역에서 개미다운 이동, 짧은 침 전투, 귀환 모험의 성격을 검증하는 것이다. 구현 완료 판단은 이 문서의 검수 기준을 실제 플레이로 확인한 뒤 내린다.


## 16. 최종 결혼 엔딩 — v0.2 추가

### 16.1 사용자 확정 사항

- 최종 엔딩은 **개미와 베짱이의 결혼**이다.
- 그동안의 진행 현황에 따라 결혼의 모습이 달라진다.
- 엔딩은 아래 5종이다. 명칭과 장면의 핵심은 사용자 지정 사항이다.
- **‘현모양처 개미’가 가장 희귀한 엔딩**이다.
- 구체적인 분기 조건·배우자의 정체·배경 장소·대사·등장 시점은 아직 확정하지 않았다.

| 번호 | 엔딩 | 반드시 표현할 핵심 장면 |
|---|---|---|
| 1 | 평범한 개미-베짱이 부부 | 개미와 베짱이가 평범한 부부로 함께 들어가는 모습 |
| 2 | 베짱이 멱살을 잡고 들어가는 개미 | 개미가 베짱이의 멱살을 잡고 들어가는 모습 |
| 3 | 베짱이 다리를 잡고 끌고 들어가는 개미 | 개미가 베짱이의 다리를 잡아 끌고 들어가는 모습 |
| 4 | 개미를 업고 들어가는 베짱이 | 베짱이가 개미를 업고 들어가는 모습 |
| 5 | 현모양처 개미 | 모험 중 장난스럽던 개미가 배우자를 살뜰히 챙기는 반전. 5종 중 가장 희귀 |

장면의 ‘들어가는 곳’은 신혼집 입구로 제안한다. 최종 장소는 추후 확정한다. 멱살·다리 끌기는 기존 만화풍에 맞춘 과장된 몸짓으로 연출한다.

### 16.2 전체 이야기 연결 — 설계 제안

1. **악연:** 챠챠를 놀리다 길을 잃고, 통행료를 요구하는 베짱이들과 충돌한다.
2. **재회:** 특정 베짱이와 반복해서 만나며 적대 관계가 조금씩 달라진다.
3. **동행:** 공통의 장애물을 넘고, 도움을 주고받는 사건에서 관계가 형성된다.
4. **귀환:** 귀갓길을 찾는 초반 목표를 해결하고, 함께 지낼 상대와의 관계를 마무리한다.
5. **결혼:** 전체 여정을 정산해 다섯 결혼 장면 중 하나를 보여준다.

배우자는 이야기 속 한 명의 고유한 베짱이로 정하고, 일반 적과 구분할 것을 제안한다. 거실의 베짱이 대장을 배우자로 자동 지정하지 않는다. 해당 인물의 정체는 별도 결정 사항이다.

진행에 따른 분기는 마지막 선택 하나보다 누적 행동으로 결정하는 방식을 제안한다. 연애 선택지 화면을 반복하기보다, 액션 중 도움·동행·상호작용과 짧은 주요 대화에 관계 변화를 담는다.

### 16.3 엔딩별 진행 성향 — 초기 제안

| 엔딩 | 연결할 진행 성향 | 구체적인 행동 예시 |
|---|---|---|
| 1. 평범한 부부 | 특별한 한쪽 성향에 치우치지 않은 관계 | 도움과 장난이 적당히 섞인 일반 진행 |
| 2. 멱살 입장 | 개미가 주도하고 상대를 자주 재촉한 관계 | 선택 가능한 장난·재촉 이벤트를 여러 번 수행 |
| 3. 다리 끌기 입장 | 개미의 밀어붙이기가 극단적으로 쌓인 관계 | 경고 반응 후에도 선택형 강행 이벤트를 반복하고 전용 후반 사건 달성 |
| 4. 업혀 입장 | 베짱이의 도움과 보호를 많이 받은 관계 | 제안받은 도움·구조·운반을 수락하며 동행 진행 |
| 5. 현모양처 | 배려와 협동을 꾸준히 쌓고 거친 장난을 자제한 관계 | 고유한 배려 사건, 자발적 도움, 협동 과제를 모두 달성 |

‘현모양처’는 사용자가 정한 엔딩 명칭으로 유지한다. 주인공이 갑자기 다른 인물이 되기보다, 평소 장난기 사이에 쌓아 온 다정함이 마지막 장면에서 드러나게 연출한다.

### 16.4 분기 판정 — 초기 제안

**서로 다른 고유 이벤트의 완료 이력**으로 관계 지표를 계산한다. 첫 설계에서는 아래 네 지표를 각각 0~100으로 정규화하는 방식을 제안한다.

| 지표 | 증가시키는 행동 | 집계 원칙 |
|---|---|---|
| 배려 | 먹이 나누기, 상대를 위해 위험을 해결하기 | 고유한 배려 사건마다 한 번 |
| 협동 | 서로의 행동을 이용해 장애물 돌파하기 | 고유한 동행 과제마다 한 번 |
| 강행 | 선택 가능한 재촉·거친 장난·상대 의견 무시 | 배우자 관련 지정 사건만 반영 |
| 도움받기 | 배우자가 제안하는 구조·운반·지원을 수락 | 고유한 도움 사건마다 한 번 |

임계값과 사건 배점은 후속 스테이지 수에 맞춰 조정한다. 아래는 모호한 중복 판정을 막기 위한 판정 순서와 임시 조건이다.

| 판정 순서 | 조건 초기안 | 결과 |
|---|---|---|
| 1 | 배려 80 이상, 협동 80 이상, 강행 20 이하, 전용 관계 사건 모두 달성 | 5. 현모양처 개미 |
| 2 | 강행 70 이상, 전용 후반 강행 사건 달성 | 3. 다리 끌기 입장 |
| 3 | 강행 40 이상 | 2. 멱살 입장 |
| 4 | 도움받기 60 이상 | 4. 업혀 입장 |
| 5 | 위 조건에 해당하지 않음 | 1. 평범한 부부 |

판정은 위에서 아래로 진행하고, 처음 충족한 엔딩 한 개만 선택한다. 5번은 확률 추첨 없이 가장 엄격한 복합 조건으로 희귀하게 만드는 것을 제안한다. 실제로 가장 희귀해지는지는 플레이 결과로 확인하고 조건을 조정한다. 번호는 엔딩 식별 번호이며 우열 점수가 아니다.

### 16.5 기존 액션 규칙과의 연결 — 설계 보완안

- 필수 전투의 침 발사·보스 공격은 강행 지표에 넣지 않는다. 진행에 필요한 행동 때문에 엔딩 5가 막히지 않게 한다.
- 피격·하트 소진·느린 클리어 자체는 강행이나 도움받기로 간주하지 않는다. 액션 숙련도와 관계 행동을 구분한다.
- 도움받기는 관계 이벤트에서 실제로 도움을 수락한 경우만 집계한다. 체크포인트 부활과 구분한다.
- 설탕 잔액·강화 구매량만으로 엔딩을 정하지 않는다. 성장에 재화를 써도 배려 루트를 완성할 수 있게 한다.
- 같은 맵·체크포인트·대사를 반복해도 같은 관계 사건으로 점수를 여러 번 올릴 수 없게 한다.
- 관계 사건도 임시 기록과 확정 기록을 나누고 체크포인트·클리어에서 확정하는 방식을 제안한다. 재시작 시 미확정 사건과 지표를 함께 되돌린다.
- 클리어한 구간을 재플레이해도 이미 확정한 고유 사건의 점수를 중복 반영하지 않는다. 다른 엔딩을 위한 전체 여정 재시작·사건 재선택 방식은 후속 설계 항목이다.
- 엔딩 5는 무피격·무사망·최고 속도·완전 강화 같은 숙련 조건 대신, 서로 다른 배려·협동 사건의 완주로 희귀하게 만드는 것을 제안한다.

### 16.6 연출·안내 — 초기 제안

모든 엔딩은 결혼이라는 공통 결말을 유지한다. 같은 신혼집 입구 구도를 활용하되 자세·표정·입장 동작·마지막 한마디를 바꿔 다섯 장면을 구분한다. 엔딩 5는 개미가 베짱이의 옷매무새를 정리하고 함께 들어가는 등 돌봄과 다정함을 행동으로 표현한다.

진행 중에는 상대의 반응과 짧은 대사로 관계 성향을 알려준다. 마지막에 갑자기 분기된 것처럼 느껴지지 않게 하며, 엔딩 화면에서는 해당 결말에 영향을 준 대표 사건을 간단히 보여주는 것을 제안한다.

엔딩 명칭·이미지·감상 기록을 모으는 갤러리는 후속 기능 제안이며, 첫 거실 검수 버전에 추가 확정된 기능은 아니다.

### 16.7 첫 버전 적용 범위와 후속 저장 설계

사용 저장소와 최종 엔딩 방향은 이번 문서에 확정 반영한다. 첫 제작 범위인 거실 한 스테이지는 유지하며, 거실 클리어를 최종 결혼 엔딩으로 처리하지 않는다. 결혼 장면과 관계 이벤트의 실제 구현은 전체 이야기 확장 단계에서 진행한다.

후속 구현 시 아래 데이터를 저장할 수 있도록 설계할 것을 제안한다.

| 데이터 | 용도 |
|---|---|
| 전체 여정 식별자 | 스테이지 설탕 재배치 회차와 이야기 진행 단위 구분 |
| 고유 관계 사건 식별자·선택 결과 | 반복 집계 방지와 엔딩 판정 근거 |
| 임시/확정 관계 기록 | 체크포인트 실패·이어 하기와 일치 |
| 엔딩 판정 규칙 버전 | 밸런스 개정 전후 기록 해석 |
| 획득 엔딩 번호·감상 이력 | 엔딩 결과 저장 |

관계 지표는 사건 기록에서 재계산 가능하게 해, 사건과 점수가 서로 어긋나는 것을 방지한다. 기존 저장에는 새 필드를 기본값으로 보완하되, 아직 플레이할 수 없었던 관계 사건을 실패·미달로 판정하지 않는다.

### 16.8 후속 검수 기준

- 다섯 엔딩 각각에 도달 가능한 실제 행동 경로가 존재한다.
- 모든 조건이 겹쳐도 하나만 출력되며, 미충족 시 평범한 부부로 귀결된다.
- 엔딩 5는 랜덤 추첨이 아니라 복합 조건으로 달성 가능하고, 가장 드물게 획득되는지 확인한다.
- 필수 전투·재도전·강화만으로 엔딩 5가 차단되지 않는다.
- 체크포인트 재시작·재접속·스테이지 재플레이로 관계 지표를 중복 획득할 수 없다.
- 엔딩 직전 종료 후 이어 해도 같은 확정 진행 이력에서 같은 결말이 나온다.
- 엔딩 결과 저장은 설탕·강화·기존 최고 기록을 훼손하지 않는다.
- 거실 1개 검수 버전은 최종 엔딩을 표시하지 않고 클리어·강화로 정상 연결된다.

## 17. v0.2 변경 기록

- 사용할 저장소를 dreamingchick/ant-adventure로 명시했다.
- 초반 귀환 동기를 유지하면서 전체 결말을 개미·베짱이의 결혼으로 확장했다.
- 사용자 지정 결혼 엔딩 5종과 현모양처 엔딩의 최희귀 조건을 확정 사항으로 추가했다.
- 진행 이력·관계 지표·분기 우선순위·중복 집계 방지·후속 검수 기준은 설계 제안으로 추가했다.
- 첫 제작 범위는 거실 1개로 유지했다. 저장소 변경이나 게임 구현·배포는 이번 문서 수정에 포함되지 않는다.
